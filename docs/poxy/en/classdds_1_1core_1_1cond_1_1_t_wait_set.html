dds::core::cond::TWaitSet class

#include <gurumdds/cpp/core/cond/WaitSet.hpp>

Waits for attached conditions to become active.

Contents

    • Constructors, destructors, conversion operators

Attach the conditions that define when the application should resume. A guard condition represents a signal from the application, a status condition represents selected communication status changes, and a read condition represents the availability of samples that match the reader's state masks.

Call wait(timeout) and use the returned condition handles to decide which status to inspect or which reader to service. The result contains condition handles. Each associated entity supplies the underlying status or sample data. For conditions whose source can change while the application runs, check the condition or entity again before acting.

Use one waiting thread per WaitSet. Finish changing attachments before waiting. The C++ wrapper uses the unsynchronized attachment list to map native wait results to condition handles.

Attaches a condition to the WaitSet.

Parameters
cond in Condition to attach
Returns This WaitSet

Attach each condition once and keep the object that owns the native condition alive until detachment. The C++ wrapper appends a handle to its local list on every call, before asking the C library to attach it. Repeating the call can therefore create duplicate entries in conditions() even when the native set already contains the condition.

Threading

Finish attaching conditions before a thread begins waiting on this WaitSet.

template <typename DELEGATE>
const ConditionSeq dds::core::cond::TWaitSet::wait(const dds::core::Duration& timeout)

Waits for active conditions up to a time limit.

Parameters
timeout in Maximum wait duration passed to the C library
Returns Active conditions, or an empty sequence if the wait reports none

The native wait checks the attached conditions before blocking, so an already-active condition can be returned immediately. Pass dds::core::Duration::zero() to poll, or pass a finite duration to bound the wait.

The C++ wrapper reads the native condition sequence and discards the native return code. An empty result can mean a timeout or a native rejection, such as a second waiter on the same WaitSet. It cannot distinguish the two.

Threading

Use one waiting thread per WaitSet. Finish changing its attachments before starting the wait.

template <typename DELEGATE>
const ConditionSeq dds::core::cond::TWaitSet::wait()

Waits for active conditions with the default timeout.

Returns Active conditions reported by the wait

Passes dds::core::Duration::infinite() to the timed overload. Its nanosecond field differs from the C library's infinity marker, and this wrapper forwards the fields unchanged. Use wait(timeout) with an explicit finite duration when the application needs a known wait limit.
