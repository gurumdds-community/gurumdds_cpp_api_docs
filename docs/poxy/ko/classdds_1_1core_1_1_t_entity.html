DDS Entity handle에 대한 일반적인 작업을 제공합니다.

DomainParticipant, Topic, Publisher, Subscriber, DataWriter, DataReader가 이 연산들을 공통으로 사용합니다. Entity handle의 복사본은 원본과 같은 구현 객체를 공유합니다. Entity별 QoS 접근 함수, listener 연산 및 상태 조회 함수는 해당 파생 타입에서 제공합니다.

handle이 비어 있을 수 있습니다. dds::core::null와 비교하여 handle을 확인한 후에만 구현 객체에게 전달할 수 있습니다.

template <typename DELEGATE>
void dds::core::TEntity::enable()

C 레이어가 이 Entity를 사용할 수 있도록 요청

새 Entity의 자동 활성화는 생성 주체의 EntityFactory QoS 정책으로 정합니다. 수동으로 활성화할 때는 생성 주체를 먼저 활성화하세요.

래퍼는 요청을 C API로 전달하고 상태 코드를 버린다. 따라서 일반적인 반환은 Entity가 요청을 받아들였음을 확인하지 않는다.

네이티브 Entity를 구현 객체에 의해 보존된 것으로 표시합니다

공유 구현 객체의 네이티브 소유권 표식을 설정합니다. 같은 구현 객체를 공유하는 다른 handle에서도 이 표식을 볼 수 있습니다. DomainParticipant처럼 표식을 확인하는 소멸자는 표식이 설정돼 있으면 네이티브 객체를 삭제하지 않습니다. 이 호출로는 모든 소유 handle이 해제된 뒤 C++ 구현 객체의 수명을 연장할 수 없습니다.

반환값 기본 GurumDDS 구현 객체로 상태 마스크 비우기

기본 구현 객체는 대기 중인 통신 이벤트와 관계없이 빈 상태 마스크를 반환합니다. 상태 변화에 대응하려면 StatusCondition에서 상태를 선택하거나 listener를 등록하세요. 횟수와 관련 handle은 해당 Entity의 상태를 읽어 얻을 수 있습니다.
