Topic은 domain 안에서 메시지 타입에 이름을 붙입니다. 각 프로세스가 별도의 Topic 객체를 만들더라도 Topic 이름이 같고 타입이 호환되면 DataWriter와 DataReader가 매칭될 수 있습니다. 이 튜토리얼은 생성된 Hello::Msg 타입을 사용합니다.

DomainParticipant 에서 만든 participant를 사용합니다. Topic을 만들려면 sample 타입도 필요합니다. 예제 빌드는 아래 IDL에서 Hello::Msg와 C++ 타입 지원 코드를 생성합니다.

IDL에서 keyed type이란?

IDL(Interface Definition Language)은 송신과 수신이 주고받는 필드를 정의하는 언어입니다. 하나 이상의 필드에 @key를 지정하면 keyed type이 됩니다. DDS는 그 필드의 값으로 같은 Topic 안의 instance를 구분합니다.

Hello::Msg의 key는 userId이고 message는 전송할 문자열입니다. userId가 7인 sample을 다시 보내면 문자열이 달라져도 같은 instance의 갱신입니다. userId가 8인 sample은 다른 instance에 속합니다.

module Hello {

    struct Msg {

        @key

        long userId;

        string message;

    };

};

위 스키마가 instance의 식별 방식을 정합니다. 다음 단계에서는 이 스키마에서 생성한 C++ 타입을 HowToEntities라는 Topic 이름과 연결합니다. userId는 DataWriter에 보낼 sample을 채울 때 지정합니다. Topic 생성자에는 DomainParticipant와 Topic 이름을 전달합니다.

Topic을 생성하고 타입 확인하기

name()은 discovery에 쓰는 Topic 이름을, type_name()은 DDS에 등록한 타입 이름을 반환합니다. 아래 예제에서 둘 다 확인합니다.

dds::topic::Topic<Hello::Msg> topic(participant, "HowToEntities");

const auto registered_type = dds::topic::topic_type_name<Hello::Msg>::value();

require(topic.name() == "HowToEntities" and topic.type_name() == registered_type, "Topic description differs");

DataWriter와 DataReader를 만들 때 이 Topic을 사용하세요. 타입 지원 코드를 직접 만들려면 endpoint 튜토리얼을 읽은 뒤 IDL에서 C++ 코드 생성 및 적용 를 따라 하세요.
