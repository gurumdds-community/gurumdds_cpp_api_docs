Subscriber와 DataReader의 클래스 관계

sample 수신과 선택

첫 번째 sample 송수신 가이드를 따라 서로 연결되는 DataWriter와 DataReader를 생성하세요. 이 가이드에서는 데이터 타입을 지정한 dds::sub::DataReader<T> 를 사용해 history에서 레코드를 읽거나 가져오고 선택하는 방법을 설명합니다.

DataReader 기록에 액세스하는 방법 선택

목적 호출 일치하는 레코드에 어떤 일이 일어나는가
기록 검사 및 사용 가능한 상태 유지 reader.read() DataReader는 레코드를 보존하고 읽음 상태로 표시합니다. 이후 호출에서 읽지 않은 sample만 선택하면 그 레코드들은 제외됩니다.
배치 소비 reader.take() DataReader는 반환한 sample을 history에서 제거합니다. 이후 read()나 take()로 같은 sample을 다시 받을 수 없습니다.
상태, instance 또는 카운트로 배치 제한 reader.select() 뒤에 read() 또는 take()가 따른다. 선택자가 지정한 필터를 적용합니다. 마지막에 호출하는 연산에 따라 레코드를 보존하거나 제거합니다.

DataReader에서 직접 호출하는 연산에는 default_filter_state()가 적용됩니다. 새 선택자는 모든 sample, 뷰, instance state와 일치하는 자체 필터로 시작합니다. 범위를 좁혀야 하면 선택자의 상태를 명시하세요. 세 상태 마스크는 dds::sub::status::DataState 항목을 참조하세요.

빈 결과 진단

read()나 take()는 조건에 맞는 레코드가 없거나 메모리 할당 또는 C 라이브러리 호출이 실패하면 빈 결과를 반환할 수 있습니다. subscription_matched_status().current_count()로 Writer와 매칭됐는지 확인하세요. 새 샘플을 보낸 뒤 content filter, instance handle, sample state mask를 확인하세요. 예를 들어 read()가 샘플을 읽음으로 표시하면 읽지 않은 샘플만 선택하는 조건에서 제외됩니다. Endpoint가 매칭되지 않으면 DataWriter와 DataReader가 데이터를 교환하지 못할 때 진단하기 를 참조하세요.

매칭 상태에서 새 sample을 보낸 뒤 기본 상태로 읽은 결과와 모든 상태를 허용한 Selector 결과를 비교하세요. 둘 다 비어 있으면 필터를 원인으로 판단하기 전에 손실과 거부 상태를 확인합니다.

유실 및 거부 샘플 진단

sample_lost_status()로 전달 전 유실을 확인합니다. sample_rejected_status()로 Reader가 거부한 샘플 수와 마지막 거부 사유를 확인합니다. last_reason()에서 instance 수, 전체 샘플 수, instance별 샘플 수 중 어떤 한도에 도달했는지 확인하고 Reader의 History와 ResourceLimits 설정을 살펴보세요. last_instance_handle()은 마지막으로 거부한 샘플의 instance를 식별합니다. 여러 곳에서 변경 수가 필요하면 상태를 한 번 조회해 결과를 공유하세요.

하나의 keyed instance 추적

새 key로 sample을 하나 보내고 instance handle과 view 상태를 확인하세요. Read는 반환한 레코드를 읽음으로 표시하고 take는 제거합니다. Dispose된 instance 감지 에 따라 instance를 dispose한 뒤 payload를 읽기 전에 SampleInfo::valid()를 확인하세요.

반환된 batch에서 rank()를 읽습니다. 두 generation의 rank 비교는 instance 세대별 rank 확인 를 참조하세요.

대여받은 sample 묶음 처리

Reader history와 샘플 loan 수명

keyed sample 튜토리얼의 Hello::Msg DataReader를 사용합니다. 이 Topic 타입에는 userId와 message 필드가 있습니다.

void print_next_batch(dds::sub::DataReader<Hello::Msg>& reader)
{
const auto samples = reader.take();
for (const auto& sample : samples)
{
if (!sample.info().valid())
continue;
std::cout << sample.data().userId << ' ' << sample.data().message << '\n';
}
}

payload를 읽기 전에 SampleInfo::valid()를 확인하세요. instance 상태 변경에는 payload가 없을 수 있습니다.

sample 참조, 반복자, payload의 포인터를 사용하는 동안 dds::sub::LoanedSamples 컬렉션을 유지하세요. 애플리케이션에서 필요한 필드는 컬렉션이 소멸하기 전에 직접 소유하는 저장 공간으로 복사하세요. 예를 들어 나중에 메시지 문자열이 필요하면 loan이 유효한 동안 유효한 Hello::Msg::message로 std::string을 생성합니다.

기본 필터를 변경하지 않고 일괄 선택

DataReader 선택자와 반환 샘플

키를 사용하는 예제의 Hello::Msg처럼 message 필드가 있는 키 기반 Topic의 DataReader를 사용하세요. DataReader에서 얻은 handle을 넘겨 특정 instance의 아직 읽지 않은 레코드를 최대 여덟 개까지 가져옵니다. 지정한 키를 찾지 못했으면 모든 instance를 선택하지 않도록 handle이 비어 있는지 확인하세요.

void print_unread_instance(dds::sub::DataReader<Hello::Msg>& reader, const dds::core::InstanceHandle& handle)
{
if (handle.is_nil())
return;
const dds::sub::status::DataState unread(dds::sub::status::SampleState::not_read());
const auto samples = reader.select().instance(handle).state(unread).max_samples(8).take();
for (const auto& sample : samples)
{
if (!sample.info().valid())
continue;
std::cout << sample.data().message << '\n';
}
}

알고 있는 key의 handle은 lookup_instance()로 찾으세요. 받은 레코드의 instance는 sample.info().instance_handle()로 식별합니다.

payload 값을 기준으로 거르려면 ContentFilteredTopic에 DataReader를 생성하세요. ContentFilteredTopic을 사용하는 Subscriber 예제는 userId > 5를 만족하는 sample을 수신하는 DataReader를 보여줍니다.

복사된 기록의 대상을 선택하십시오

반복자를 받는 오버로드는 레코드와 메타데이터를 애플리케이션이 제공한 저장 공간에 씁니다. buffer.begin()과 양수를 넘기면 이미 마련된 쓰기 가능한 위치를 사용합니다. 호출 전에 버퍼에 그만큼의 공간이 있는지 확인하세요. std::back_inserter(buffer)를 넘기면 확장 가능한 컨테이너에 추가하며 메모리를 할당할 수 있습니다. 두 형태 모두 기록한 레코드 수를 반환합니다.

복사본이 payload 필드를 소유하는 Topic 타입을 사용합니다. 두 함수는 IDL에서 C++ 코드 생성 및 적용 에서 정의한 정수 필드 하나짜리 IdlExample::Message 타입과 DataReader의 기본 상태 필터를 사용합니다.

#include <gurumdds/dds.hpp>
#include <MessageTypeSupport.hpp>
#include <array>
#include <cstdint>
#include <iterator>
#include <vector>
using MessageSample = dds::sub::Sample<IdlExample::Message, dds::sub::SampleInfo>;
std::uint32_t read_into_buffer(dds::sub::DataReader<IdlExample::Message>& reader, std::array<MessageSample, 8>& buffer)
{
return reader.read(buffer.begin(), static_cast<std::uint32_t>(buffer.size()));
}
std::uint32_t append_taken_records(dds::sub::DataReader<IdlExample::Message>& reader, std::vector<MessageSample>& buffer)
{
return reader.take(std::back_inserter(buffer));
}

Topic 타입에 빌린 포인터가 있다면 loan을 사용하세요. loan이 유효한 동안 필요한 값을 직접 소유하는 필드로 복사합니다. 반복자로 레코드를 복사하는 경우에는 Topic 타입의 C++ 복사 의미론을 따릅니다.

선택 결과의 복사 개수를 제한하려면 선택자에 직접 max_samples(n)을 설정하세요. 순방향 반복자를 받는 선택자 오버로드가 이 값을 사용합니다. 용량이 고정된 저장 공간에는 쓸 수 있는 위치의 개수 이하인 양수를 지정합니다.

경고
반복자를 받는 take()는 복사 전에 레코드를 history에서 제거합니다. 대입이나 삽입이 실패하면 대상에 일부만 남을 수 있습니다. 제거한 레코드는 history로 돌아오지 않습니다.

처리 및 등록 해제를 통해 instance 추적

첫 번째 sample 송수신 의 예제 빌드 방법을 따라 example_cpp_helloworld_keyed_subscriber와 example_cpp_helloworld_keyed_publisher를 빌드합니다. Subscriber를 먼저 실행하세요. 두 프로그램 모두 domain 79와 Topic HelloWorld를 사용하며, 데이터 타입의 키는 userId입니다.

key를 사용하는 Publisher 는 세 개의 키를 기록합니다. userId가 1인 경우에는 키를 등록하고 hello를 기록한 다음, instance 폐기를 명시적으로 요청합니다. 이후 같은 키로 world를 기록한 뒤 키 등록을 취소합니다.

키가 있는 Subscriber 는 아직 읽지 않은 레코드를 한 번에 최대 여덟 개까지 읽고 키와 instance state를 출력합니다.

키 1에 대한 Publisher 작업 Subscriber에 대해 찾아야 할 것
hello를 쓰세요 값 hello를 가진 ALIVE
instance 처리 NOT_ALIVE_DISPOSED
world를 쓰세요 값 world를 가진 ALIVE
키에 대한 마지막 DataWriter 등록 해제 NOT_ALIVE_NO_WRITERS
같은 key의 instance 상태 변화
Instance 상태와 Reader purge delay

이 순서는 예제의 DataWriter만 해당 키에 데이터를 쓰고, Publisher가 실행되는 동안 Subscriber가 데이터를 읽는다고 가정합니다. Publisher는 등록 취소 시 자동 폐기를 비활성화하므로, 마지막 등록 취소에서 해당 instance의 DataWriter가 없어진 상태를 관찰할 수 있습니다. 자동 폐기를 활성화하면 등록 취소와 함께 폐기도 요청합니다.

Subscriber는 상태 알림 레코드의 instance_handle()을 key_value()에 넘겨 키를 얻습니다. valid()가 true를 반환할 때만 payload 필드를 읽습니다. NOT_ALIVE_NO_WRITERS 상태를 관찰한 뒤 선택자를 사용해 저장해 둔 handle의 레코드 중 아직 남은 것을 가져옵니다. Subscriber가 레코드를 받지 못하면 DataWriter와 DataReader가 데이터를 교환하지 못할 때 진단하기 항목을 참조하세요.
