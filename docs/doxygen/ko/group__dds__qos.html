상세한 설명

Entity 설정과 endpoint 호환성에 쓰는 정책입니다.

Entity마다 지원하는 QoS 정책이 다릅니다. 생성 전에 정책을 설정하거나 생성 후 QoS 설정 함수를 호출하세요.

호환성은 매칭 정책 에서, 설정이 적용된 경로는 Entity의 QoS 출처 에서, 연결 진단은 DataWriter와 DataReader가 데이터를 교환하지 못할 때 진단하기 에서 확인하세요.

QoS 정책 요약

표는 초기 기본값입니다. 설정이나 Publisher 및 Subscriber의 기본 QoS에 따라 달라질 수 있습니다. 실제 값은 각 Entity의 QoS에서 확인하세요.

매칭 영향은 DataWriter와 DataReader의 호환 여부를 기준으로 합니다. DataWriter는 생성할 때 정책을 설정하세요.

매칭 정책

정책 적용 대상 초기 기본값 설정 시점 매칭 영향
Reliability Topic, DataWriter, DataReader DataWriter는 RELIABLE, Topic과 DataReader는 BEST_EFFORT. 생성 시 있음
Durability Topic, DataWriter, DataReader VOLATILE 생성 시 있음
Deadline Topic, DataWriter, DataReader 무한 주기 Topic의 QoS setter. Endpoint 타이머는 생성 시 설정. 있음
DestinationOrder Topic, DataWriter, DataReader BY_RECEPTION_TIMESTAMP 생성 시 있음
LatencyBudget Topic, DataWriter, DataReader 0초 Topic과 DataReader의 QoS setter. DataWriter는 생성 시 설정. 있음
Liveliness Topic, DataWriter, DataReader AUTOMATIC, 무한 lease 생성 시 있음
Ownership Topic, DataWriter, DataReader SHARED 생성 시 있음
Partition Publisher, Subscriber 기본 partition(빈 이름) QoS setter 있음
Presentation Publisher, Subscriber INSTANCE. Coherent access와 ordered access는 비활성화. 생성 시 있음
제공 QoS와 요청 QoS의 호환 조건

DataReader의 QoS를 변경하면 상대 endpoint에 알리는 Deadline 값도 바뀔 수 있습니다. Reader의 deadline 타이머에는 생성 시 설정한 주기가 적용됩니다.

DDS Security를 사용하면 DataWriter를 만들기 전에 Publisher의 partition을 설정하세요.

보관 및 전달 정책

정책 적용 대상 초기 기본값 설정 시점 매칭 영향
History Topic, DataWriter, DataReader KEEP_LAST, depth는 LENGTH_UNLIMITED 생성 시 없음
ResourceLimits Topic, DataWriter, DataReader 한도 세 가지 모두 LENGTH_UNLIMITED 생성 시 없음
Lifespan Topic, DataWriter 무한 시간 Topic의 QoS setter. DataWriter는 생성 시 설정. 없음
OwnershipStrength DataWriter 0 생성 시 없음
ReaderDataLifecycle DataReader writer가 없으면 무한, dispose 시 0 생성 시 없음
TimeBasedFilter DataReader 최소 간격 0초 생성 시 없음
WriterDataLifecycle DataWriter 등록 해제 시 자동 dispose 생성 시 없음

OwnershipStrength는 매칭된 writer 중 EXCLUSIVE instance를 담당할 writer를 결정합니다. 필터와 삭제 지연을 적용하려면 reader를 생성할 때 TimeBasedFilter와 ReaderDataLifecycle을 설정하세요.

QoS를 지정하지 않고 DataWriter 또는 DataReader 생성 해당 Endpoint에 대한 Publisher 또는 Subscriber의 현재 기본값입니다.

호환 조건은 DataWriter와 DataReader가 데이터를 교환하지 못할 때 진단하기 에서, 예제는 QoS와 sample 전달 에서 확인하세요.

DataWriter와 DataReader가 데이터를 교환하지 못할 때 진단하기

DDS가 discovery를 마칠 때까지 DataWriter와 DataReader를 하나씩 실행해 두세요. 빌드와 실행 명령은 첫 번째 sample 송수신 에 있습니다.

Endpoint 매칭과 샘플 선택 조건 확인

endpoint 구성 확인

  1. DomainParticipant의 domain ID를 비교하세요. Publisher와 Subscriber는 같은 DDS domain에 참여해야 합니다. 두 프로세스가 실행 중이며 지정한 네트워크에서 서로를 발견할 수 있는지 확인하세요.
  2. 양쪽의 Topic 이름, 등록한 타입, 필드 정의, key를 비교하세요.
  3. Publisher와 Subscriber의 Partition을 비교합니다. 양쪽에서 일치하는 항목이 하나 이상 있어야 합니다. 어느 쪽이든 와일드카드를 사용할 수 있습니다. 예를 들어 plant.*는 plant.line1과 일치합니다. 목록이 비어 있으면 이름이 빈 문자열인 기본 Partition을 사용합니다.
  4. endpoint의 QoS를 비교하세요. DataWriter는 서비스 수준을 제공하고 DataReader는 서비스 수준을 요청합니다. 아래의 matching 횟수와 비호환 QoS 횟수를 확인해 DDS가 두 endpoint를 연결했는지 판단합니다.
  5. endpoint가 연결됐다면 새 sample을 기록하고 DataReader가 어떤 sample을 선택하는지 확인하세요. content filter는 sample을 제외할 수 있습니다. 상태 또는 instance 필터에 따라 특정 읽기나 가져오기 연산에서 sample이 빠질 수도 있습니다. payload에 접근하기 전에 sample.info().valid()를 확인하세요. 수신 연산은 sample 수신과 선택 항목을 참조해 선택하세요.

두 프로세스에서 topic.name()과 topic.type_name()을 출력하세요. Topic 이름이 같으면 등록 타입과 IDL의 필드 및 key를 따로 비교합니다.

두 PC에서 실행할 때 진단

먼저 한 PC에서 두 프로세스 예제를 실행하세요. 각 PC에서 실행 파일이 의도한 SDK와 바인딩을 로드하는지 확인하고, PC마다 endpoint 하나씩 실행합니다. 매칭 수가 0이면 인터페이스와 네트워크 규칙이 DDS discovery를 허용하는지 확인하세요. 매칭 뒤에는 새 sample을 보내고 DataReader의 필터와 상태를 확인합니다.

관련 QoS 정책 비교

정책 설정 대상 비교 항목
Partition Publisher 및 Subscriber 양쪽 항목이 이름이나 와일드카드로 하나 이상 일치합니다.
Reliability DataWriter 및 DataReader RELIABLE DataReader에는 RELIABLE DataWriter가 필요합니다. BEST_EFFORT DataReader는 두 종류의 DataWriter와 모두 연결할 수 있습니다.
Durability DataWriter 및 DataReader TRANSIENT_LOCAL DataReader에는 TRANSIENT_LOCAL DataWriter가 필요합니다. VOLATILE DataReader는 두 종류의 DataWriter와 모두 연결할 수 있습니다.
Deadline DataWriter 및 DataReader DataWriter가 제공하는 갱신 주기는 DataReader가 요청한 주기보다 작거나 같아야 합니다.
History DataWriter 및 DataReader instance별 sample 보존을 제어합니다. 각 endpoint는 history 종류와 깊이를 개별 설정할 수 있습니다.

이 점검에서는 endpoint를 만들 때 사용할 정책을 명시하세요. Reliability, Durability 또는 History를 변경하려면 DataReader나 DataWriter를 다시 생성합니다. 기록 이후에 연결된 DataReader에도 보존한 sample을 전달하려면 양쪽에 TRANSIENT_LOCAL을 지정하고 sample 보존을 설정하세요. 정책별 설명은 Quality of Service 항목을 참조하세요.

상태 스냅샷 읽기

DataReader에서는 subscription_matched_status().current_count()를, DataWriter에서는 publication_matched_status().current_count()를 확인하세요. 값이 양수이면 현재 연결된 상대 endpoint가 하나 이상 있습니다. 누적 matching 횟수는 상대 endpoint가 종료한 뒤에도 양수로 남을 수 있습니다.

DataReader의 requested_incompatible_qos_status()와 DataWriter의 offered_incompatible_qos_staus()를 확인하세요. 새 시험에서 total_count()가 양수이면 DDS가 호환되지 않는 QoS 설정을 발견한 것입니다. last_policy_id()로 가장 최근에 보고된 정책을 확인할 수 있습니다. 횟수가 계속 0이면 발견, Topic, Partition 설정을 계속 점검하세요. 둘 이상의 구성 요소에서 변화량이 필요하면 반환된 스냅샷을 보관합니다. 상태를 읽으면 해당 변화량은 0으로 초기화되고 Entity의 해당 변경 플래그가 해제됩니다.

wait_for_acknowledgments()는 이미 발행한 sample을 대상으로 합니다. 연결된 reliable DataReader가 없어도 예외 없이 반환할 수 있으므로, 상대 endpoint의 존재 여부는 매칭 상태를 확인하세요. 예외 처리와 다른 방식으로 실패를 보고하는 호출은 오류와 스레드 항목을 참조하세요.

두 소스 파일에 <chrono>와 <thread>를 추가하세요. 점검하는 동안 Publisher가 실행 상태를 유지하도록 기록 호출 뒤에 std::this_thread::sleep_for(std::chrono::seconds(10));을 추가합니다. Subscriber의 무한 수신 루프를 아래 진단 루프로 바꾸세요. 5초의 진단 시간 안에 Subscriber를 먼저, Publisher를 나중에 시작합니다.

const auto end = std::chrono::steady_clock::now() + std::chrono::seconds(5);
bool has_reported = false;
while (std::chrono::steady_clock::now() < end)
{
if (dr.subscription_matched_status().current_count() > 0)
{
std::cout << "Reader matched a writer\n";
has_reported = true;
break;
}
const auto incompatible = dr.requested_incompatible_qos_status();
if (incompatible.total_count() > 0)
{
const auto policy = incompatible.last_policy_id();
if (policy == dds::core::policy::policy_id<dds::core::policy::Reliability>::value)
std::cout << "Reliability mismatch\n";
else
std::cout << "Incompatible QoS policy " << policy << '\n';
has_reported = true;
break;
}
std::this_thread::sleep_for(std::chrono::milliseconds(100));
}
if (!has_reported)
std::cout << "No match or incompatible QoS reported within five seconds\n";

best-effort DataWriter와 reliable DataReader를 사용하면 상대 발견 후 Reliability mismatch가 출력됩니다. Publisher의 BestEffort()를 Reliable(dds::core::Duration::from_millisecs(100))으로 바꾼 뒤 빌드하고 두 프로세스를 다시 실행하세요. 나머지 설정이 같으면 Reader matched a writer가 출력됩니다. 데이터 수신을 확인하려면 Hello World Subscriber 의 수신 루프를 복구하고 호환되는 DataWriter와 함께 실행합니다.
