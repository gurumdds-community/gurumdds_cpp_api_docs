Linux에서 C++ 바인딩 빌드 및 송수신 확인

GCC 버전, 아키텍처, C++ 표준 라이브러리 ABI에 맞는 Conan 1 프로필을 사용합니다. gcc-release를 사용할 프로필 이름으로 바꾸고 C++ 바인딩 저장소 최상위에서 실행합니다.

conan install . -if build/tutorials --build=missing -pr gcc-release -s build_type=Release
cmake -S . -B build/tutorials -DCMAKE_BUILD_TYPE=Release -DBUILD_EXAMPLE=ON
cmake --build build/tutorials --target example_cpp_programming_howto
./build/tutorials/bin/example_cpp_programming_howto

CMake 4를 사용한다면 저장소의 이전 CMake 설정을 읽을 수 있도록 구성 명령에 -DCMAKE_POLICY_VERSION_MINIMUM=3.5를 추가합니다.

로더가 공유 라이브러리를 찾지 못하면 libgurumdds.so와 libgurumdds_psm_cxx.so가 있는 디렉터리를 LD_LIBRARY_PATH에 추가합니다. Release 빌드는 다른 프로젝트에서도 사용할 수 있도록 라이브러리와 헤더를 각각 output/lib와 output/include에 복사합니다.

프로그램은 한 프로세스에서 양쪽 Endpoint를 생성하고 매칭을 기다린 뒤 read와 take를 한 번씩 확인합니다. 성공하면 아래 문장을 출력합니다. 코드는 reliable 전송과 수신 에서 확인합니다.

Received: Hello from the how-to

Linux에서 두 프로세스 예제 실행

같은 빌드 디렉터리에 Legacy Publisher와 Subscriber를 빌드합니다.

cmake --build build/tutorials --target sub_cpp pub_cpp

한 터미널에서 Subscriber를 실행합니다.

./build/tutorials/bin/sub_cpp

두 번째 터미널에서도 같은 SDK 실행 환경을 설정하고 저장소 최상위에서 Publisher를 실행합니다.

./build/tutorials/bin/pub_cpp

두 프로세스는 모두 Domain 0에 참여하고 HelloWorld Topic을 사용합니다. Subscriber는 sample을 받으면 Hello!를 출력합니다. Legacy Publisher는 500 ms를 기다린 뒤 한 번 전송합니다. Discovery에 시간이 더 걸리면 DataWriter와 DataReader가 데이터를 교환하지 못할 때 진단하기 를 확인합니다. 소스는 Hello World Publisher 과 Hello World Subscriber 에 있습니다.

설치된 SDK로 빌드

IDL에서 C++ 코드 생성 및 적용 에서 C++ 타입을 생성하고 Topic을 등록합니다. 이 CMake 프로젝트는 GURUMDDS_ROOT에서 네이티브 SDK를, GURUMDDS_CXX_ROOT에서 C++ 바인딩을 찾습니다. 생성한 타입 지원 코드를 컴파일하고 두 라이브러리를 링크합니다. 이미 생성된 타입 지원 코드가 있다면 같은 헤더 경로와 링크 설정을 사용합니다.

설치된 SDK에서 통신을 확인하려면 C++17 컴파일러로 Hello World 를 빌드하고 Subscriber와 Publisher를 실행합니다. Subscriber는 Received HelloWorld와 payload를 출력합니다.
