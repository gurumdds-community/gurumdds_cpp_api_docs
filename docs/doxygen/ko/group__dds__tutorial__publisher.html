Publisher
Programming Tutorials

Publisher는 자신을 통해 생성한 DataWriter를 관리합니다. DomainParticipant로 Publisher를 만든 뒤 타입이 지정된 Topic과 함께 DataWriter 생성자에 전달하세요. 먼저 Publisher 설정을 마칩니다.

DomainParticipant 에서 만든 participant를 사용합니다. Topic과 keyed type 에서 만든 Topic은 다음 장에서 DataWriter에 전달합니다. 여기서는 이 Publisher를 통해 생성할 DataWriter의 공통 발행 설정을 정합니다.

Publisher 생성

이 생성자는 DomainParticipant의 기본 Publisher QoS를 사용합니다. 송신과 수신 양쪽에서 기본 partition을 쓰는 애플리케이션에 사용할 수 있습니다.

dds::pub::Publisher publisher(participant);

별도 설정이 없으면 Publisher는 이름이 없는 partition을 사용합니다. 다음 예제에서는 howto라는 partition으로 Publisher를 만듭니다. 대응하는 Subscriber 예제에서도 이 이름을 사용합니다.

Publisher의 Partition 설정하기

DataWriter 생성 전에 Publisher의 Partition을 설정하세요. howto처럼 이름을 직접 지정했다면 수신 Subscriber에도 같은 이름을 쓰세요.

auto publisher_qos = participant.default_publisher_qos();
publisher_qos << Partition("howto");
dds::pub::Publisher publisher(participant, publisher_qos);

Publisher가 속한 DomainParticipant 가져오기

publisher.participant()로 Publisher를 생성할 때 사용한 DomainParticipant를 가져오세요. 독립적으로 보관하려면 handle을 복사하세요.

const auto owner = publisher.participant();
require(owner == participant, "Publisher belongs to another participant");

Publisher의 Partition은 소속 DataWriter에 적용됩니다. DataWriter QoS는 개별 DataWriter의 동작을 정합니다. 다음 코드에서는 기본 History 깊이를 설정한 뒤 그 값을 상속하는 DataWriter를 만듭니다.

새 DataWriter의 기본 QoS 설정하기

Publisher의 기본 QoS를 읽고 원하는 정책을 바꾼 다음 default_writer_qos(qos)를 호출합니다. 이후 QoS를 따로 지정하지 않고 생성한 DataWriter에는 이 기본값이 적용됩니다. 예제에서는 실제로 적용된 history depth를 확인합니다.

auto writer_defaults = publisher.default_writer_qos();
writer_defaults << History::KeepLast(3);
publisher.default_writer_qos(writer_defaults);
dds::pub::DataWriter<Hello::Msg> writer(publisher, topic);
require(writer.qos().policy<History>().depth() == 3, "Writer did not inherit history depth");
