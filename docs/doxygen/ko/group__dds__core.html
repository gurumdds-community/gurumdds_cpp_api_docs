상세한 설명

DDS 공통 타입과 서비스입니다.

시간 간격에는 duration을, 타임스탬프에는 time을, 이벤트를 기다릴 때는 condition을 사용합니다.

오류와 스레드

재시도하기 전에 반환값을 확인하세요. 각 연산에 명시된 예외를 처리하세요.

DDS 예외 처리

네이티브 오류를 변환하는 연산은 dds::core::Exception 의 파생 타입을 던집니다. 예외별로 대응할 수 있으면 그 타입을 잡으세요. 호출자에게 실패를 알리는 경계에서는 기본 타입을 잡으세요.

  • dds::core::InvalidArgumentError 또는 dds::core::PreconditionNotMetError 가 발생하면 애플리케이션에서 인수, Entity 상태, 호출 순서를 확인하세요.
  • dds::core::NotEnabledError 는 활성화된 Entity에서만 연산을 실행할 수 있음을 나타냅니다.
  • dds::core::InconsistentPolicyError 가 발생하면 정책 조합을 확인하세요.
  • dds::core::ImmutablePolicyError 는 setter가 변경을 거부했다는 뜻입니다. Entity를 만들 때 Reliability, History 등 생성 시점의 정책을 설정하세요. 정책을 바꾸려면 원하는 QoS로 Entity를 다시 만드세요.
  • dds::core::TimeoutError 또는 dds::core::OutOfResourcesError 는 지정된 시간 안에 연산을 마치지 못했거나 DDS가 필요한 리소스를 확보하지 못했음을 나타냅니다. 정확한 발생 조건은 함수마다 다릅니다.

다음 함수는 활성화된 reliable DataWriter를 받아 대기 중인 수신 확인이 도착할 때까지 최대 250 ms 동안 기다립니다. 시간 초과를 처리하며 다른 실패는 호출자에게 전달합니다.

#include <gurumdds/dds.hpp>
template <typename T>
bool wait_for_ack(dds::pub::DataWriter<T>& writer)
{
try
{
writer.wait_for_acknowledgments(dds::core::Duration::from_millisecs(250));
return true;
}
catch (const dds::core::TimeoutError&)
{
return false;
}
}

매칭된 Reliable DataReader가 없어도 확인 응답 대기가 성공할 수 있습니다. 상대 endpoint의 매칭 여부는 DataWriter와 DataReader가 데이터를 교환하지 못할 때 진단하기 에서 설명하는 상태로 확인하세요.

dds::core::cond::TWaitSet 에서 대기하는 연산의 반환 규약은 다릅니다. 트리거된 조건을 시퀀스로 반환합니다. 시퀀스가 비어 있으면 어떤 조건도 보고하지 않은 이유까지는 알 수 없습니다.

WaitSet 조정

WaitSet마다 대기 스레드를 하나만 사용하세요. 대기 전에 condition 연결과 해제를 마치세요. 대기가 끝날 때까지 WaitSet과 condition 소유 객체를 유지하세요. 유한한 timeout을 지정하면 스레드가 종료 요청을 확인할 수 있습니다. 반환된 condition에 따라 Entity 상태를 읽거나 일치하는 sample을 꺼내세요.

listener와 함께 작업하기

애플리케이션이 listener를 소유합니다. 등록 중과 callback이 끝날 때까지 listener를 유지하세요. 다른 스레드와 공유하는 상태는 동기화하세요. callback은 오래 걸리는 작업을 작업 스레드에 넘길 수 있습니다. LoanedSamples를 해제하기 전에 작업 스레드가 쓸 sample 데이터를 복사하세요.

구독 쪽에서는 활성화된 dds::sub::SubscriberListener::on_data_on_readers() callback이 DataReader의 데이터 도착 callback보다 우선합니다. Subscriber callback은 dds::sub::TSubscriber::notify_datareaders() 를 호출해 해당 DataReader의 callback 실행을 예약할 수 있습니다. sample 접근과 loan 수명은 sample 수신과 선택 항목을 참조하세요.

Listener 등록 범위와 해제

Endpoint 하나의 이벤트는 타입이 지정된 DataReader 또는 DataWriter Listener를 사용합니다. 데이터 도착을 묶어 받으려면 Subscriber Listener를 사용하세요. 부모 객체에 등록할 때는 그 부모가 제공하는 콜백 타입과 상태 마스크를 사용합니다.

종료할 때는 새 작업 전달을 멈춥니다. Entity가 지원하는 Listener setter로 등록을 해제하세요. 콜백과 loaned sample을 사용하는 작업이 끝나면 loan 소유자와 Listener를 해제합니다.
