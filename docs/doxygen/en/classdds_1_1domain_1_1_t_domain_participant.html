dds::domain::DomainParticipant

#include <gurumdds/cpp/domain/DomainParticipant.hpp>

Detailed Description

Joins a DDS domain and owns the entities created within it.

A domain ID identifies a DDS communication domain. Participants using the same domain ID can discover each other, subject to discovery configuration. Different domain IDs let independent DDS applications share the same physical network.

Create topics, publishers, and subscribers through a participant. Use different participants in one process to join different domains.

Creates a participant and configures its listener.

The default GurumDDS delegate reads the factory's default participant QoS for this overload. To apply custom policies, call qos(const dds::domain::qos::DomainParticipantQos&) or configure the factory defaults before construction when creation-time settings are required.

template<typename DELEGATE>
void dds::domain::DomainParticipant< DELEGATE >::assert_liveliness ( )

Manually asserts liveliness through the participant.

For writers configured with MANUAL_BY_PARTICIPANT liveliness, service activity from the participant maintains their liveliness. Call this operation within the configured lease duration during periods when publication alone does not provide that activity. Use the writer's own assertion for MANUAL_BY_TOPIC.
