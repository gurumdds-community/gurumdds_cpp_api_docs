Subscribers
Programming Tutorials

A Subscriber owns the DataReaders created through it. Give the Subscriber your DomainParticipant, then create a reader with a Topic from that participant. A Subscriber's Partition policy applies to its readers.

On the receiving side, start with a DomainParticipant in the writer's domain. Name its receive-side handle participant. Use the sender's partition settings when you want the reader to match that writer.

Create a Subscriber

The constructor below uses the participant's default Subscriber QoS. For a named partition, set the Subscriber QoS before creating its readers.

dds::sub::Subscriber subscriber(participant);

Set the receiving partition

Create the subscriber with the same literal partition name as the publisher. The reader belongs to this subscriber and uses its partition when discovering writers.

auto subscriber_qos = participant.default_subscriber_qos();
subscriber_qos << Partition("howto");
dds::sub::Subscriber subscriber(participant, subscriber_qos);

The previous sections configured the Subscriber. This step reads its default DataReader QoS and changes History for one reader, then passes that QoS explicitly when creating the reader.

Use subscriber defaults to configure a reader

Copy the subscriber default reader QoS and extract its History policy. Edit the policy, set it back on the QoS copy, then pass that copy to the reader constructor. The subscriber keeps its original defaults.

auto reader_qos = subscriber.default_datareader_qos();
auto reader_history = reader_qos.policy<History>();
reader_history.kind(dds::core::policy::HistoryKind::KEEP_LAST).depth(2);
reader_qos.policy(reader_history);
dds::sub::DataReader<T> reader(subscriber, topic, reader_qos);
require(reader.qos().policy<History>().depth() == 2, "Reader did not use the requested history depth");

Check the Subscriber's domain and Partition

Use participant().domain_id() to check the Subscriber's domain. Read Partition from its current QoS and compare the names with the publishing side.

const auto subscriber_domain = subscriber.participant().domain_id();
const auto subscriber_partitions = subscriber.qos().policy<Partition>().name();
require(subscriber_domain == domain, "Subscriber domain differs");
require(subscriber_partitions == dds::core::StringSeq{"howto"}, "Subscriber Partition differs");

Verify which partition receives a sample

A writer and two readers use the same domain and topic. One reader belongs to a Subscriber in the writer's howto partition. The other belongs to a Subscriber in other.

Send one sample and verify that only the matched reader receives it.

Domain and Partition matching boundaries
auto other_qos = participant.default_subscriber_qos();
other_qos << Partition("other");
dds::sub::Subscriber other_subscriber(participant, other_qos);
dds::sub::DataReader<T> other_reader(other_subscriber, topic, reader_qos);
howto::wait_for_readers(writer, 1);
char message[] = "partition example";
Hello::Msg sample{};
sample.userId = 7;
sample.message = message;
writer.write(sample);
howto::wait_until([&reader, &sample]() -> bool {
const auto batch = reader.take();
for (const auto& received : batch)
if (received.info().valid() and received.data().userId == sample.userId)
return true;
return false;
}, "The reader in the matching partition did not receive the sample");
require(writer.publication_matched_status().current_count() == 1, "Expected exactly one matched reader");
require(other_reader.subscription_matched_status().current_count() == 0, "The reader in the other partition matched");
require(other_reader.take().length() == 0, "The reader in the other partition received data");

A Subscriber can receive an aggregate notification for its readers. The example below follows one sample through on_data_on_readers() and the corresponding reader callback.

Route data notifications from a Subscriber to its Reader

Enable data_on_readers on the Subscriber and data_available on the DataReader. Each callback sets an atomic flag.

After the Subscriber callback signals data, call notify_datareaders() from the application thread. Wait for the Reader callback, then take the sample.

class SubscriberDataReady : public dds::sub::SubscriberListener, public dds::sub::NoOpAnyDataReaderListener
{
public:
std::atomic<bool> is_notified{ false };
void on_data_on_readers(dds::sub::Subscriber&) override
{
is_notified.store(true);
}
};
class ReaderDataReady : public dds::sub::NoOpDataReaderListener<Hello::Msg>
{
public:
std::atomic<bool> is_notified{ false };
void on_data_available(dds::sub::DataReader<Hello::Msg>&) override
{
is_notified.store(true);
}
};
dds::sub::Subscriber subscriber(participant, participant.default_subscriber_qos(), &subscriber_listener,
StatusMask::data_on_readers());
dds::sub::DataReader<T> reader(subscriber, topic, subscriber.default_datareader_qos(), &reader_listener,
StatusMask::data_available());
dds::pub::DataWriter<T> writer(publisher, topic);
howto::wait_for_readers(writer, 1);
howto::wait_until([&subscriber_listener]() -> bool { return subscriber_listener.is_notified.load(); },
"The Subscriber listener did not receive on_data_on_readers");
howto::require(not reader_listener.is_notified.load(), "The Reader already received on_data_available");
subscriber.notify_datareaders();
howto::wait_until([&reader_listener]() -> bool { return reader_listener.is_notified.load(); },
"The Reader listener did not receive on_data_available");
const auto batch = reader.take();
howto::require(batch.length() == 1 and batch.begin()->info().valid() and batch.begin()->data().userId == 7,
"The sample was not available after the Reader notification");

Subscriber and Reader notifications

Checks the Subscriber callback, schedules the Reader notification, and takes the sample.

Build the program with the command below. A successful run prints Subscriber notification example passed.

cmake --build . --target example_cpp_howto_subscriber_listener
Complete source
#include <atomic>
#include "demo.hpp"
namespace
{
// [subscriber_callback_types]
class SubscriberDataReady : public dds::sub::SubscriberListener, public dds::sub::NoOpAnyDataReaderListener
{
public:
std::atomic<bool> is_notified{ false };
void on_data_on_readers(dds::sub::Subscriber&) override
{
is_notified.store(true);
}
};
class ReaderDataReady : public dds::sub::NoOpDataReaderListener<Hello::Msg>
{
public:
std::atomic<bool> is_notified{ false };
void on_data_available(dds::sub::DataReader<Hello::Msg>&) override
{
is_notified.store(true);
}
};
// [subscriber_callback_types]
void route_data_notifications()
{
dds::domain::DomainParticipant participant(105);
dds::topic::Topic<T> topic(participant, "HowToSubscriberListener");
dds::pub::Publisher publisher(participant);
SubscriberDataReady subscriber_listener;
ReaderDataReady reader_listener;
using dds::core::status::StatusMask;
// [subscriber_callback_setup]
dds::sub::Subscriber subscriber(participant, participant.default_subscriber_qos(), &subscriber_listener,
StatusMask::data_on_readers());
dds::sub::DataReader<T> reader(subscriber, topic, subscriber.default_datareader_qos(), &reader_listener,
StatusMask::data_available());
dds::pub::DataWriter<T> writer(publisher, topic);
howto::wait_for_readers(writer, 1);
// [subscriber_callback_setup]
char message[] = "subscriber notification";
Hello::Msg sample{};
sample.userId = 7;
sample.message = message;
writer.write(sample);
// [defer_reader_notification]
howto::wait_until([&subscriber_listener]() -> bool { return subscriber_listener.is_notified.load(); },
"The Subscriber listener did not receive on_data_on_readers");
howto::require(not reader_listener.is_notified.load(), "The Reader already received on_data_available");
subscriber.notify_datareaders();
howto::wait_until([&reader_listener]() -> bool { return reader_listener.is_notified.load(); },
"The Reader listener did not receive on_data_available");
const auto batch = reader.take();
howto::require(batch.length() == 1 and batch.begin()->info().valid() and batch.begin()->data().userId == 7,
"The sample was not available after the Reader notification");
// [defer_reader_notification]
std::cout << "Listener order: Subscriber first, Reader after notify_datareaders()\n";
}
}
int main()
{
return howto::run(route_data_notifications, "Subscriber notification example passed");
}
