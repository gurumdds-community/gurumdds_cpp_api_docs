template<typename DELEGATE>
class dds::sub::TCoherentAccess< DELEGATE >

Exposes the subscriber coherent-access scope.

The default delegate calls the C begin-access operation from end(). This binding does not provide a working begin/end pair.

template<typename DELEGATE>
dds::sub::TCoherentAccess< DELEGATE >::TCoherentAccess ( const dds::sub::Subscriber & sub)
inlineexplicit

Constructs a coherent-access object for the Subscriber.

This operation indicates that the application is about to access the data samples in any of the DataReader<T> objects attached to the Subscriber. The application needs this operation only if PRESENTATION QosPolicy of the Subscriber to which the DataReader<T> belongs has the access_scope set to "GROUP." In that case, the operation begin_access must be called prior to calling any of the sample-accessing operations, namely: data_readers on the Subscriber and read, take, read_w_condition, take_w_condition on any DataReader<T>. Otherwise the sample-accessing operations will return the error PRECONDITION_NOT_MET. Once the application has finished accessing the data samples it must call end_access. It is not required for the application to call begin_access/end_access if the PRESENTATION QosPolicy has the access_scope set to something other than GROUP. Calling begin_access/end_access in this case is not considered an error and has no effect. The calls to begin_access/end_access may be nested. In that case, the application must call end_access as many times as it called begin_access.
