Topics and keyed types
Programming Tutorials

A Topic gives a message type a name within a domain. A writer and reader match on compatible types and the same topic name, even when each process creates its own Topic object. This tutorial uses the generated Hello::Msg type.

Start with participant from Domain participants. To create a Topic, you also need a sample type. The example build generates Hello::Msg and its C++ type support from the IDL shown below.

What makes an IDL type keyed?

IDL stands for Interface Definition Language. It defines the fields that the sender and receiver exchange. An IDL type is keyed when one or more fields are marked @key. DDS uses those field values to tell instances of the same Topic apart.

In Hello::Msg, userId is the key and message carries the text. Sending another sample with userId 7 updates the same instance even if the text changes. A sample with userId 8 belongs to a different instance.

module Hello {
struct Msg {
@key
long userId;
string message;
};
};

The schema above determines how to identify an instance. The next step pairs that schema's C++ type with the topic name HowToEntities. Supply userId when filling a sample for the writer. The Topic constructor takes the participant and the topic name.

Create a topic and check its type

Check name() for the name used in discovery and type_name() for the name of the type registered with DDS. Both are shown in the example.

dds::topic::Topic<Hello::Msg> topic(participant, "HowToEntities");
const auto registered_type = dds::topic::topic_type_name<Hello::Msg>::value();
require(topic.name() == "HowToEntities" and topic.type_name() == registered_type, "Topic description differs");

Use this Topic when creating a DataWriter or DataReader. To generate the type support yourself, follow Generate and use C++ code from IDL after the endpoint tutorials.
