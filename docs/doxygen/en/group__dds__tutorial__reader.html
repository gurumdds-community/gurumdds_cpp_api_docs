Data readers
Programming Tutorials

A DataReader receives samples of its Topic type and stores them in its history. Create it with a Subscriber and Topic from the same participant. Use read() to inspect a sample and leave it in history. Use take() to remove it.

Use subscriber from Subscribers and the receive-side topic of type Topic<Hello::Msg>. The reader's template argument must match the Topic's sample type.

Create a DataReader

dds::sub::DataReader<Hello::Msg> reader(subscriber, topic);
dds::sub::DataReader<T>
Receives typed samples for a topic.

Read the SampleInfo before using the payload. An instance state change can arrive without valid data. Keep a returned loan alive while you use its samples.

The complete send-and-receive program matches a reliable writer and reader before it writes one sample. The snippets below start after that write. The unread and read filters let the program first inspect the record and then take the same record.

Read a sample and then remove it

Select unread samples and call read(). The reader marks the returned samples as read and keeps them in its history. In this example the helper polls for a valid payload for up to two seconds.

std::string read_message(dds::sub::DataReader<Hello::Msg>& reader)
{
const dds::sub::status::DataState unread(dds::sub::status::SampleState::not_read());
const auto deadline = std::chrono::steady_clock::now() + std::chrono::seconds(2);
while (std::chrono::steady_clock::now() < deadline)
{
{
const auto samples = reader.select().state(unread).read();
for (const auto& sample : samples)
{
if (sample.info().valid())
return std::string(sample.data().message);
}
}
std::this_thread::sleep_for(std::chrono::milliseconds(20));
}
throw std::runtime_error("No valid sample was read within two seconds");
}

Check SampleInfo::valid() before accessing a payload, then copy the message while the loan is alive. After the read loan goes out of scope, select read samples and use take() to remove them. Each operation can return a batch. This example sends only one sample and checks that both calls return its payload.

std::string take_read_message(dds::sub::DataReader<Hello::Msg>& reader)
{
const dds::sub::status::DataState already_read(dds::sub::status::SampleState::read());
const auto samples = reader.select().state(already_read).take();
for (const auto& sample : samples)
{
if (sample.info().valid())
return std::string(sample.data().message);
}
throw std::runtime_error("No previously read sample with a valid payload was taken");
}

Inspect source timestamps and payload validity

Select unread samples and inspect SampleInfo. Check valid() before accessing data(). The example checks the received source timestamp against the timestamp supplied to the writer.

howto::wait_until([&reader, &sent_at]() -> bool {
const auto samples = reader.select().state(DataState::new_data()).read();
for (const auto& sample : samples)
{
if (not sample.info().valid())
continue;
const auto timestamp = sample.info().timestamp();
require(timestamp.sec() == sent_at.sec() and timestamp.nanosec() == sent_at.nanosec(), "Timestamp differs");
if (sample.data().userId == 7)
return true;
}
return false;
}, "Timestamped sample did not arrive");

Up to this point the sample is used inside the loan's scope. To keep data for later, copy any borrowed fields before the loan ends. This example switches from Hello::Msg to Tutorial::Reading to show a string, a fixed array, and a sequence together.

Keep generated fields after returning a loan

module Tutorial
{
struct Reading
{
long id;
string label;
long bounds[2];
sequence<long> values;
};
};

In the generated Tutorial::Reading struct, the fixed array is stored inline. Copying the struct copies the array elements and shares the string and sequence pointers.

Copy the string and sequence contents into application-owned containers while the loan is alive. The example checks the owned values after the loan ends.

Ownership of fields copied from a loaned IDL value
std::string owned_label;
std::array<dds_Long, 2> owned_bounds{};
std::vector<dds_Long> owned_values;
howto::wait_until([&]() -> bool {
const auto samples = reader.take();
for (const auto& sample : samples)
{
if (not sample.info().valid() or sample.data().id != 7)
continue;
const auto& received = sample.data();
const Tutorial::Reading shallow_copy = received;
howto::require(shallow_copy.label == received.label and shallow_copy.values == received.values,
"Expected the generated copy to share the string and sequence pointers");
owned_label = shallow_copy.label;
owned_bounds = {{ shallow_copy.bounds[0], shallow_copy.bounds[1] }};
for (uint32_t i = 0; i < dds_LongSeq_length(shallow_copy.values); ++i)
owned_values.push_back(dds_LongSeq_get(shallow_copy.values, i));
return true;
}
return false;
}, "No generated Reading arrived");
howto::require(owned_label == "outside temperature", "The copied string differs");
howto::require(owned_bounds == std::array<dds_Long, 2>{{ -20, 50 }}, "The copied array differs");
howto::require(owned_values == std::vector<dds_Long>{ 12, 34 }, "The copied sequence differs");

Select one sample for a key

Use lookup_instance() on the reader to get its handle for the key. Pass that handle to the selector, then set max_samples(1) to limit the read to one record. The loan goes out of scope while the sample remains in the reader's history.

const auto reader_handle = reader.lookup_instance(message);
require(not reader_handle.is_nil(), "Reader has no handle for this key");
{
const auto selected = reader.select().instance(reader_handle).max_samples(1).read();
require(selected.length() == 1, "Expected one record for the selected instance");
const auto& sample = *selected.begin();
require(sample.info().valid() and sample.data().userId == message.userId, "Selected a different instance");
}

Take read and unread samples separately

Combine SampleState and InstanceState to select records by both conditions. This example leaves ViewState unrestricted.

Read the sample for key 7 without removing it from the reader. Then send key 8. Take read records from alive instances first, then take unread records. The two calls return different keys.

Select read and unread records independently
const DataState unread_alive(SampleState::not_read(), ViewState::any(), InstanceState::alive());
const DataState read_alive(SampleState::read(), ViewState::any(), InstanceState::alive());
writer.write(sample);
howto::wait_until([&reader, &unread_alive]() -> bool {
const auto batch = reader.select().state(unread_alive).read();
return batch.length() == 1 and batch.begin()->info().valid() and batch.begin()->data().userId == 7;
}, "Key 7 did not arrive as unread data");
sample.userId = 8;
writer.write(sample);
{
const auto read = reader.select().state(read_alive).take();
howto::require(read.length() == 1 and read.begin()->info().valid() and read.begin()->data().userId == 7,
"Expected only the previously read key");
}
howto::wait_until([&reader, &unread_alive]() -> bool {
const auto batch = reader.select().state(unread_alive).take();
return batch.length() == 1 and batch.begin()->info().valid() and batch.begin()->data().userId == 8;
}, "Expected only the unread key");

Detect a disposed instance

Use the reader's instance handle to identify the key. A dispose notification in this example has valid() set to false and an instance state of not_alive_disposed(). Check SampleInfo and leave the payload untouched.

The full example sets a longer ReaderDataLifecycle purge delay before creating the reader so it can observe the notification.

howto::wait_until([&reader, &reader_handle]() -> bool {
const auto samples = reader.take();
for (const auto& sample : samples)
{
const auto& info = sample.info();
if (info.instance_handle() == reader_handle
and not info.valid()
and info.state().instance_state() == InstanceState::not_alive_disposed())
return true;
}
return false;
}, "The reader did not observe the dispose notification");

Inspect ranks across instance generations

Read a sample without removing it, dispose the instance, then write again with the same key. This keeps valid samples from both generations in the reader history.

char first[] = "before dispose";
char second[] = "after dispose";
Hello::Msg value{};
value.userId = 42;
value.message = first;
const auto handle = writer.register_instance(value);
writer.write(value, handle);
howto::wait_until([&reader]() -> bool {
const auto samples = reader.read();
return samples.length() == 1 and samples.begin()->info().valid();
}, "The first generation did not arrive");
writer.dispose_instance(handle);
value.message = second;
writer.write(value, handle);

Print the sample, generation, and absolute generation ranks reported by SampleInfo::rank(). The comparison depends on the returned batch and the reader history.

howto::wait_until([&reader]() -> bool {
const auto batch = reader.read();
unsigned int valid_count = 0;
for (const auto& sample : batch)
if (sample.info().valid())
++valid_count;
if (valid_count != 2)
return false;
std::cout << "payload | sample | generation | absolute generation\n";
for (const auto& sample : batch)
{
if (not sample.info().valid())
continue;
const auto rank = sample.info().rank();
std::cout << sample.data().message << " | " << rank.sample() << " | "
<< rank.generation() << " | " << rank.absolute_generation() << '\n';
}
return true;
}, "Expected two generations in the same read batch");

Reliable send and receive

Configures reliable endpoints, waits for discovery, sends one sample, then reads and removes it.

Build the program with the command below. A successful run prints Received: Hello from the how-to.

#include <chrono>
#include <ciso646>
#include <cstdlib>
#include <exception>
#include <iostream>
#include <stdexcept>
#include <string>
#include <thread>
#include <gurumdds/dds.hpp>
#include <HelloWorldTypeSupport.hpp>
namespace
{
// [wait_for_match]
void wait_for_match(dds::pub::DataWriter<Hello::Msg>& writer, dds::sub::DataReader<Hello::Msg>& reader)
{
const auto deadline = std::chrono::steady_clock::now() + std::chrono::seconds(5);
while (std::chrono::steady_clock::now() < deadline)
{
const auto writer_match = writer.publication_matched_status();
const auto reader_match = reader.subscription_matched_status();
if (writer_match.current_count() > 0 and reader_match.current_count() > 0)
return;
std::this_thread::sleep_for(std::chrono::milliseconds(20));
}
throw std::runtime_error("No writer and reader match within five seconds");
}

while (std::chrono::steady_clock::now() < deadline)
{
{

for (const auto& sample : samples)
{
if (sample.info().valid())
return std::string(sample.data().message);
}
}
std::this_thread::sleep_for(std::chrono::milliseconds(20));
}
throw std::runtime_error("No valid sample was read within two seconds");
}

int main()
{
try
{
dds::domain::DomainParticipant participant(91);
dds::topic::Topic<Hello::Msg> topic(participant, "GurumDDSProgrammingHowTo");
dds::pub::Publisher publisher(participant);
dds::sub::Subscriber subscriber(participant);
// [reliable_endpoints]
using dds::core::policy::History;
using dds::core::policy::Reliability;
const auto reliable = Reliability::Reliable(dds::core::Duration::from_millisecs(200));
auto writer_qos = publisher.default_writer_qos();
writer_qos << reliable << History::KeepLast(4);
auto reader_qos = subscriber.default_datareader_qos();
reader_qos << reliable << History::KeepLast(4);
dds::pub::DataWriter<Hello::Msg> writer(publisher, topic, writer_qos);
dds::sub::DataReader<Hello::Msg> reader(subscriber, topic, reader_qos);
// [reliable_endpoints]
// [publish_after_match]
wait_for_match(writer, reader);
char message[] = "Hello from the how-to";
Hello::Msg sample{};
sample.userId = 1;
sample.message = message;
writer.write(sample);
// [publish_after_match]
const std::string received = read_message(reader);
const std::string removed = take_read_message(reader);
if (received != message or removed != message)
throw std::runtime_error("The read and take did not return the sent message");
std::cout << "Received: " << received << '\n';
}
catch (const std::exception& error)
{
std::cerr << error.what() << '\n';
return EXIT_FAILURE;
}
return EXIT_SUCCESS;
}

Generated type and field ownership

Exchanges a sample of the generated type and keeps copies of its fields after the loan ends.

Build the program with the command below. A successful run prints Generated IDL and field ownership examples passed.
